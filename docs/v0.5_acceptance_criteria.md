# ResearchAgent v0.5 验收标准

## 1. v0.5 目标

v0.5 的目标是把 ResearchAgent 从“记录 accept/reject 修订决策”升级为“生成可人工确认的 manuscript patch 草稿”。系统仍然是本地 demo 级科研草稿系统，不做公网生产化、不接真实科研软件、不引入队列或数据库架构升级。

核心目标：

- accepted revision decision 可以生成 proposed manuscript patch。
- patch preview 可以被前端查看。
- patch 必须经过人工确认或拒绝。
- confirmed patch 只能生成新的 manuscript version，不能覆盖 `manuscript/draft.md`。
- patch 必须保留 issue、decision、claim 和 evidence provenance。
- audit log 增加本地 hash chain，用于辅助完整性检查，但不声明为生产级不可篡改审计。

## 2. 必须保护的 v0.4 基线

- `scripts/validate_v01.py`、`validate_v02.py`、`validate_v03.py`、`validate_v04.py` 必须继续通过。
- 不得破坏以下核心输出：
  - `literature/literature_index.json`
  - `literature/metadata_history.jsonl`
  - `literature/parsed/*.txt`
  - `literature/parsed/*.metadata.json`
  - `analysis/result_summary.json`
  - `analysis/analysis_provenance.json`
  - `figures/figure_provenance.json`
  - `provenance/evidence.json`
  - `provenance/claim_alignment.json`
  - `manuscript/draft.md`
  - `manuscript/refined.md`
  - `reviews/review_report.json`
  - `reviews/revision_decisions.jsonl`
  - `audit/audit_log.jsonl`
  - `runs/run_history.json`
- 不得破坏 `claim_id` 稳定性、Evidence Checklist、Claim Alignment 和 Reviewer sentence-level issue 检查。
- 不得伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性或因果结论。
- 不得把 placeholder 文献自动标记为 verified。
- 不得把 AI 生成图伪装成实验图。
- patch、version、decision 操作必须写入 audit log；confirmed patch 必须写入 manuscript version history。

## 3. Manuscript Patch 生成验收标准

新增工具：

- `services/api/app/tools/manuscript_patch.py`

新增输出目录：

- `projects/{project_id}/manuscript/patches/`

新增 patch 文件：

- `projects/{project_id}/manuscript/patches/patch_{patch_id}.json`

patch JSON 必须包含：

- `patch_id`
- `source_manuscript`
- `base_version_id`
- `created_at`
- `status="proposed"`
- `source="accepted_revision_decision"`
- `items`
- `summary`

每个 patch item 必须包含：

- `patch_item_id`
- `issue_id`
- `decision_id`
- `section`
- `paragraph_index`
- `sentence_index`
- `before`
- `after`
- `change_type`
- `related_claim_id`
- `evidence_status`
- `requires_human_confirmation=true`
- `warnings`

验收要求：

- 只基于 accepted revision decisions 生成 patch。
- rejected decision 不得进入 patch。
- `revision_diff` 缺失时不得生成 patch item。
- `revision_diff.requires_human_approval` 不是 true 时，必须强制人工确认或阻断 item。
- patch 初始状态必须是 `proposed`。
- 生成 patch 不得修改 `manuscript/draft.md`。
- patch 必须保留 `issue_id`、`decision_id`、`related_claim_id`。
- patch 不得新增事实、p 值、DOI、真实引用或因果结论。
- patch 不得修改数字和单位。
- patch 生成必须写入 audit log。

## 4. Patch Safety 验收标准

新增工具：

- `services/api/app/tools/patch_safety.py`

每个 patch item 必须经过安全检查，输出：

```json
{
  "safe": true,
  "warnings": [],
  "blocked_reasons": []
}
```

必须检查：

- `before` 存在于 `draft.md`。
- `after` 不能为空。
- 数字未被修改。
- 单位未被修改。
- `after` 不包含 p 值。
- `after` 不包含 DOI。
- `after` 不包含强结论词。
- `related_claim_id` 如果存在，必须在 `evidence.json` 中存在。

不安全 item 不得进入最终可应用版本。patch summary 必须记录 blocked item 数量和原因摘要。

## 5. Patch Preview 验收标准

新增文件：

- `projects/{project_id}/manuscript/patches/patch_{patch_id}.preview.md`

preview 必须包含：

- patch id
- source manuscript
- status
- 每个 patch item 的 section、issue id、decision id、related claim、change type
- before / after 对照
- warnings
- blocked item 摘要

新增 API：

- `GET /api/projects/{project_id}/manuscript/patches/{patch_id}/preview`

验收要求：

- API 可以返回 preview markdown 内容。
- preview 缺失时返回 404。
- preview 不修改 manuscript。

## 6. Patch 人工确认验收标准

新增 API：

- `POST /api/projects/{project_id}/manuscript/patches/{patch_id}/confirm`

输入：

```json
{
  "decision": "confirmed",
  "reason": "manual confirmation"
}
```

或：

```json
{
  "decision": "rejected",
  "reason": "not suitable"
}
```

验收要求：

- 只能确认或拒绝已存在且 status 为 `proposed` 的 patch。
- rejected patch 不得生成 manuscript version。
- confirmed patch 必须生成新的 manuscript version。
- confirm/reject 必须更新 patch status。
- confirm/reject 必须写入 audit log。
- confirm 后仍不得覆盖 `manuscript/draft.md`。

## 7. Manuscript Versioning 验收标准

新增目录：

- `projects/{project_id}/manuscript/versions/`

新增文件：

- `projects/{project_id}/manuscript/versions/manuscript_v001.md`
- `projects/{project_id}/manuscript/versions/version_history.json`

`version_history.json` 结构必须包含：

```json
{
  "versions": [
    {
      "version_id": "manuscript_v001",
      "file": "manuscript/versions/manuscript_v001.md",
      "base_file": "manuscript/draft.md",
      "created_at": "...",
      "source_patch_id": "patch_001",
      "source_decision_ids": [],
      "source_issue_ids": [],
      "status": "created",
      "summary": {
        "applied_items": 1,
        "skipped_items": 0,
        "warnings": []
      }
    }
  ]
}
```

验收要求：

- version 生成必须读取 base manuscript 并按 `before` 文本安全替换。
- 如果无法定位 `before`，必须跳过 item 并记录 skipped item，不得强行替换。
- 新版本必须保留 Evidence Checklist。
- 新版本必须保留原有 claim_id。
- 新版本不得新增 unsupported claim、p 值、DOI 或强结论。
- version 生成必须写入 audit log。

新增 API：

- `GET /api/projects/{project_id}/manuscript/versions`
- `GET /api/projects/{project_id}/manuscript/versions/{version_id}`

## 8. Audit Hash Chain 验收标准

扩展工具：

- `services/api/app/tools/audit_log.py`

每行 audit log 必须新增：

- `prev_hash`
- `entry_hash`

规则：

- 第一条记录的 `prev_hash` 为 `GENESIS` 或 null。
- `entry_hash = SHA256(canonical_json_without_entry_hash)`。
- 下一条记录的 `prev_hash` 必须等于上一条记录的 `entry_hash`。
- 不做加密签名，不声明为生产级不可篡改审计。
- 不得记录 secret、API key 或内部绝对路径。

新增 API：

- `GET /api/projects/{project_id}/audit/verify`

返回：

```json
{
  "valid": true,
  "checked_entries": 0,
  "first_invalid_index": null,
  "errors": []
}
```

验收要求：

- 正常 audit log 校验为 valid。
- 手动篡改 audit log 后校验必须返回 invalid。
- v0.5 新增写操作必须写入 hash chain。

## 12. validate_v05.py 验收标准

新增脚本：

- `scripts/validate_v05.py`

必须检查：

- demo project 存在。
- 可以运行完整 workflow。
- v0.1、v0.2、v0.3、v0.4 验证脚本继续通过。
- 可以创建 accepted revision decision。
- 可以生成 patch JSON。
- patch status 为 `proposed`。
- patch preview 存在。
- 生成 patch 前后 `draft.md` hash 不变。
- patch safety checker 存在并能阻断危险改写。
- confirm patch 后生成 `manuscript_v001.md`。
- `version_history.json` 存在并记录 `source_patch_id`。
- confirm patch 后 `draft.md` hash 仍不变。
- audit hash chain 校验通过。
- audit verify API 返回 valid。

通过时输出：

```text
ResearchAgent v0.5 validation passed.
```

## 13. v0.5 不做的功能

- 不做用户登录。
- 不做多租户权限。
- 不做公网部署。
- 不接 PostgreSQL、Celery、Redis、LangGraph。
- 不接 MATLAB、Origin、COMSOL、ImageJ。
- 不接真实湿实验仪器。
- 不接真实 DOI 数据库。
- 不做真实 OCR。
- 不做真实查重。
- 不做完整 LaTeX 编译。
- 不伪造引用。
- 不伪造统计显著性。
- 不生成未经 evidence 支持的 Results 结论。
- 不自动覆盖原始 `manuscript/draft.md`。
