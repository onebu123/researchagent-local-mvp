# ResearchAgent v0.3 验收标准

## 1. v0.3 目标

v0.3 的目标是在 v0.2 冻结能力上，把 manuscript 正文、evidence claim 和 reviewer issue 做到可追踪对齐。v0.3 不追求炫酷功能，也不重写架构，只增强科研草稿的可信链路。

核心目标：

1. manuscript 生成后重新扫描 Results / Discussion，并与 `provenance/evidence.json` 对齐。
2. Reviewer issue 能定位到 section、paragraph、sentence。
3. 文献 metadata 可以人工编辑和人工标记 verified。
4. PDF 解析结果有质量评分和人工复核提示。
5. 数据分析结果有可复核的 analysis provenance。
6. 前端能查看 claim alignment、sentence issues、literature metadata、analysis provenance。
7. 最小 Playwright E2E 覆盖 dashboard 可信链路和 mock fallback。

## 2. 必须保护的 v0.2 边界

1. `python scripts/validate_v01.py` 必须继续通过。
2. `python scripts/validate_v02.py` 必须继续通过。
3. 不得破坏以下文件的核心字段：
   - `literature/literature_index.json`
   - `literature/parsed/*.txt`
   - `literature/parsed/*.metadata.json`
   - `analysis/result_summary.json`
   - `figures/figure_provenance.json`
   - `provenance/evidence.json`
   - `manuscript/draft.md`
   - `reviews/review_report.json`
4. 不得自动伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性或因果结论。
5. 不得把 placeholder 文献自动升级成 verified。
6. 不得把 AI 生成图伪装为实验图。
7. 后端新增 API 必须保留路径越界保护，缺文件时返回清晰 404。
8. 无 API key 环境必须继续可以跑通 demo。
9. 前端后端不可用时必须继续可以 mock 渲染。

## 3. Post-Manuscript Claim Alignment

新增 Claim Alignment Agent，工作流顺序为：

1. Literature Agent
2. Topic & Novelty Agent
3. Analysis Agent
4. Figure Agent
5. Provenance Agent
6. Manuscript Agent
7. Claim Alignment Agent
8. Refinement Agent
9. Reviewer Agent

验收标准：

1. 新增 `services/api/app/agents/claim_alignment_agent.py`。
2. 完整 workflow 后生成 `provenance/claim_alignment.json`。
3. `claim_alignment.json` 至少检查 1 个 Results 句子。
4. 至少 1 条 alignment 的 `matched_claim_id` 不为空。
5. Results 中无法匹配 evidence 的核心句子必须标记为 `needs_claim_alignment`。
6. 明显背景、方法说明或 limitation 可以标记为 `not_claim`。
7. Reviewer 必须读取 `claim_alignment.json`。
8. `validate_v03.py` 必须检查 claim alignment 文件、matched claim 和 Results sentence。

## 4. Reviewer Sentence-Level Issue

Reviewer 必须在 `reviews/review_report.json` 中新增 `sentence_issues` 字段。

每条 sentence issue 必须包含：

1. `issue_id`
2. `section`
3. `paragraph_index`
4. `sentence_index`
5. `sentence`
6. `issue_type`
7. `severity`
8. `related_claim_id`
9. `evidence_status`
10. `suggested_revision`

验收标准：

1. `claim_alignment.json` 中 `needs_claim_alignment` 的句子进入 `sentence_issues`。
2. Results / Discussion 中出现强结论词但缺少统计证据时，生成 `issue_type=overclaim`。
3. Results 中没有 `matched_claim_id` 的核心结论句生成 sentence-level issue。
4. Discussion 中没有 evidence 的过度推断生成 sentence-level issue。
5. 若存在 `severity=major`，`overall_decision` 不得高于 `major_revision`。
6. 手动在 `draft.md` 加入 `significantly improved` 后，Reviewer 必须生成 sentence-level overclaim issue。

## 5. Literature Metadata Editor

后端新增：

1. `GET /api/projects/{project_id}/literature`
2. `PATCH /api/projects/{project_id}/literature/{literature_id}`

PATCH 允许更新字段：

1. `title`
2. `authors`
3. `year`
4. `doi`
5. `journal`
6. `metadata_status`
7. `human_verified`

验收标准：

1. GET literature API 返回 `literature_index.json` 列表。
2. PATCH literature API 可以更新指定 `literature_id`。
3. title 必须非空。
4. authors 必须为字符串数组。
5. year 只能为 null 或 1500 到当前年份之间的整数。
6. doi 为空时允许；非空时必须以 `10.` 开头且包含 `/`。
7. metadata_status 只能为 `placeholder`、`extracted`、`verified`。
8. human_verified 必须为 bool。
9. 只有 `metadata_status=verified` 且 `human_verified=true` 的文献允许进入 Manuscript 的 `Verified references`。
10. API 不得自动补 DOI、作者、年份或期刊。
11. `validate_v03.py` 必须验证 PATCH 更新后 `literature_index.json` 生效。

## 6. PDF Parse Quality Report

PDF metadata 必须新增：

1. `text_length`
2. `empty_page_count`
3. `extraction_method`
4. `warning_count`
5. `quality_score`
6. `quality_label`
7. `needs_manual_review`

验收标准：

1. 每个 PDF metadata 都包含上述质量字段。
2. 解析失败时 `quality_score=0` 且 `quality_label=failed`。
3. 低文本量、高空页比例、fallback parser 或 warning 会降低质量分。
4. low / failed PDF 进入 Reviewer 的 `metadata_issues` 或 `citation_issues`。
5. 如果所有 PDF 都是低质量，`overall_decision` 不得高于 `major_revision`。
6. 前端能展示 parse_status、quality_score、quality_label、needs_manual_review。
7. `validate_v03.py` 必须检查 PDF quality 字段。

## 7. Analysis Provenance

Analysis Agent 必须生成：

`analysis/analysis_provenance.json`

验收标准：

1. 文件包含 `analysis_id`、`input_data_file`、`input_data_hash`、`analysis_function`、`generated_files`、`created_at`、`runtime`、`row_count`、`column_count`、`warnings`、`limitations`。
2. 如果使用 demo CSV，必须包含 `is_demo_data=true`。
3. runtime 至少包含 Python、pandas、numpy 版本。
4. Evidence analysis claim 必须绑定 `analysis/analysis_provenance.json`。
5. Reviewer 必须检查 analysis provenance 是否存在。
6. 缺失 analysis provenance 时必须进入 `evidence_issues` 或 `statistical_issues`。
7. `validate_v03.py` 必须检查 analysis provenance 字段。

## 9. 新增后端 API

新增：

1. `GET /api/projects/{project_id}/claim-alignment`
2. `GET /api/projects/{project_id}/analysis/provenance`
3. `GET /api/projects/{project_id}/literature`
4. `PATCH /api/projects/{project_id}/literature/{literature_id}`

## 12. validate_v03.py

新增：

`scripts/validate_v03.py`

必须检查：

1. demo_project 存在。
2. 完整 workflow 可运行。
3. v0.1/v0.2 验证仍通过或由脚本内检查覆盖。
4. `provenance/claim_alignment.json` 存在。
5. claim_alignment 至少有 1 条 matched claim。
6. claim_alignment 至少检查 Results 句子。
7. `reviews/review_report.json` 包含 `sentence_issues`。
8. `literature/literature_index.json` 包含 `metadata_status` 和 `human_verified`。
9. PDF metadata 包含质量字段。
10. `analysis/analysis_provenance.json` 存在并包含 hash、function、generated_files、runtime。
11. evidence analysis claim 绑定 analysis provenance。
12. draft.md 包含 Evidence Checklist 和 claim_id。
13. figure_provenance.json 包含 data_hash。
14. 当前 demo 的 review decision 为 `major_revision` 或 `reject`。
15. 所有新增 API 可读取对应文件。
16. 输出严格包含：

```text
ResearchAgent v0.3 validation passed.
```

## 13. 不做的功能

v0.3 不做：

1. 用户登录。
2. 多租户权限。
3. 公网部署。
4. Redis、Celery、PostgreSQL。
5. LangGraph 强制接入。
6. MATLAB、Origin、COMSOL、ImageJ。
7. 真实湿实验仪器接入。
8. 真实查重。
9. 绕过 AI 检测。
10. 完整 LaTeX 编译。
11. 复杂 UI 重构。
12. 真实 DOI 联网核验。
13. 自动生成 p 值。
14. 因果推断。
15. placeholder 自动变 verified。
16. 重写整个项目架构。
