# ResearchAgent v0.4 验收标准

## 1. v0.4 目标

v0.4 的目标是把 v0.3 的“能定位问题”升级为“能安全辅助修订问题”，同时加入最小审计日志和任务运行历史。系统仍然是本地 demo 级科研草稿系统，不做公网生产化、用户登录、多租户、队列化或数据库架构升级。

## 2. 必须实现的功能

- Reviewer sentence issue 必须包含 `revision_diff`，给出保守修订建议，但不自动改写 `draft.md`。
- 前端必须能查看修订 diff，并能记录 accept/reject 决策。
- 修订决策必须写入 `reviews/revision_decisions.jsonl`，且 `applied_to_manuscript=false`。
- 文献 metadata PATCH 必须写入 `literature/metadata_history.jsonl`。
- PDF metadata 必须包含页级质量数组和 OCR 预留字段，但 v0.4 不实际执行 OCR。
- Analysis provenance 必须记录参数、脚本版本、随机种子和输出文件 hash。
- 项目关键本地操作必须写入 `audit/audit_log.jsonl`。
- workflow 和单步运行必须写入 `runs/run_history.json`。
- 前端必须新增修订建议、文献历史、PDF 质量、审计日志和运行历史入口。
- `scripts/validate_v04.py` 必须验证 v0.1、v0.2、v0.3 回归继续通过。

## 3. 不做的功能

- 不做用户登录、多租户权限、公网部署。
- 不引入 PostgreSQL、Redis、Celery、LangGraph。
- 不接真实 DOI 数据库、OCR 引擎、湿实验仪器或科研软件。
- 不生成或伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性或因果结论。
- 不自动把 placeholder 文献标为 verified。
- 不自动把修订建议写入 manuscript。
- 不做复杂前端重构。

## 4. Revision Diff 验收标准

每个 `reviews/review_report.json` 中的 `sentence_issues[]` 必须包含：

- `can_auto_suggest`
- `before`
- `after`
- `change_type`
- `preserved_claim_id`
- `preserved_numbers`
- `preserved_units`
- `requires_human_approval=true`
- `warnings`

`change_type` 只能取：

- `conservative_rewrite`
- `remove_overclaim`
- `add_evidence_note`
- `mark_as_limitation`
- `needs_human_rewrite`

修订建议不得生成新事实、p 值、DOI、期刊或因果结论，不得删除已有 `claim_id`，不得修改数字和单位。

## 5. 修订决策日志验收标准

新增 API：

- `POST /api/projects/{project_id}/review/sentence-issues/{issue_id}/decision`
- `GET /api/projects/{project_id}/review/revision-decisions`

写入文件：

- `projects/{project_id}/reviews/revision_decisions.jsonl`

每行必须包含：

- `decision_id`
- `issue_id`
- `decision`
- `before`
- `after`
- `reason`
- `created_at`
- `source`
- `applied_to_manuscript=false`

API 只能接受已有 `issue_id`，不能修改 `draft.md`，无效 `decision` 返回 400/422。

## 6. 文献 Metadata History 验收标准

每次成功 PATCH 文献 metadata 时，必须写入：

- `projects/{project_id}/literature/metadata_history.jsonl`

每行必须包含：

- `history_id`
- `literature_id`
- `changed_fields`
- `old_values`
- `new_values`
- `changed_at`
- `source`
- `reason`

新增 API：

- `GET /api/projects/{project_id}/literature/history`
- `GET /api/projects/{project_id}/literature/{literature_id}/history`

history 不得记录 API key、secret 或内部绝对路径。

## 7. PDF 页级质量验收标准

PDF metadata 必须保留 v0.3 字段，并新增：

- `pages`
- `empty_page_count`

每个 `pages[]` 记录必须包含：

- `page_number`
- `char_count`
- `empty`
- `warnings`
- `quality_signal`
- `ocr.ocr_attempted=false`
- `ocr.ocr_engine=null`
- `ocr.ocr_status="not_configured"`
- `ocr.ocr_text_file=null`

`empty_page_count` 必须等于 `pages[].empty=true` 的数量。v0.4 不运行 OCR，不能写 OCR success。

## 8. Analysis Provenance 验收标准

`analysis/analysis_provenance.json` 必须新增：

- `parameters`
- `script_version`
- `random_seed`
- `output_file_hashes`

limitations 必须明确：

- 仅描述性分析。
- 不生成 p 值。
- 不做因果推断。

Reviewer 必须检查上述字段缺失并写入 issue。

## 9. Audit Log 验收标准

新增文件：

- `projects/{project_id}/audit/audit_log.jsonl`

至少记录：

- `create_project`
- `upload_literature`
- `upload_data`
- `run_workflow`
- `run_workflow_step`
- `patch_literature_metadata`
- `create_revision_decision`

每行必须包含：

- `audit_id`
- `event_type`
- `project_id`
- `timestamp`
- `source`
- `actor`
- `summary`
- `details`

不得包含 API key、secret 或内部绝对路径。新增 API `GET /api/projects/{project_id}/audit` 返回最近记录。

## 10. Run History 验收标准

新增文件：

- `projects/{project_id}/runs/run_history.json`

结构：

```json
{
  "runs": [
    {
      "run_id": "run_001",
      "run_type": "workflow",
      "step": null,
      "status": "completed",
      "start_time": "...",
      "end_time": "...",
      "duration_seconds": 1.23,
      "outputs": [],
      "errors": [],
      "warnings": []
    }
  ]
}
```

新增 API `GET /api/projects/{project_id}/runs`。

## 11. 前端验收标准

必须新增或扩展：

- `RevisionDiffPanel.tsx`
- `LiteratureHistoryPanel.tsx`
- `PDFQualityPanel.tsx`
- `AuditLogPanel.tsx`
- `RunHistoryPanel.tsx`
- `SentenceIssuesPanel.tsx`
- `LiteratureMetadataPanel.tsx`
- `AnalysisProvenancePanel.tsx`

Dashboard 必须新增入口：

- 查看修订建议
- 查看文献变更历史
- 查看 PDF 质量
- 查看审计日志
- 查看运行历史

后端不可用时必须继续 mock 渲染。

## 12. 新增测试要求

新增后端测试至少覆盖：

- revision_diff 结构、强结论改写和修订决策 API。
- literature metadata history 写入和读取。
- PDF 页级质量与 OCR 预留字段。
- analysis_provenance v0.4 字段。
- audit_log 写入和无绝对路径泄露。
- run_history 写入和 API 返回。

## 13. validate_v04.py 验收标准

`scripts/validate_v04.py` 必须验证：

- v0.1、v0.2、v0.3 验证脚本继续通过。
- demo workflow 可完整运行。
- sentence issue 至少一条包含完整 `revision_diff`。
- revision decision API 能写入 JSONL，且不修改 manuscript。
- literature PATCH 后生成 metadata history。
- PDF metadata 包含 `pages[]` 和 OCR not configured 字段。
- analysis provenance 包含 v0.4 新字段。
- audit log 存在且不包含内部绝对路径。
- run history 存在且至少有 completed workflow。

通过时输出：

```text
ResearchAgent v0.4 validation passed.
```
