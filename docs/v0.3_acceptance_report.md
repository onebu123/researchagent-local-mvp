# ResearchAgent v0.3 验收报告

## 1. v0.3 完成能力清单

1. Post-Manuscript Claim Alignment
   - 新增 `services/api/app/agents/claim_alignment_agent.py`。
   - workflow 顺序调整为 Literature → Topic → Analysis → Figure → Provenance → Manuscript → Claim Alignment → Refinement → Reviewer。
   - 完整 workflow 输出 `projects/demo_project/provenance/claim_alignment.json`。
   - Results / Discussion 句子会标记为 `matched`、`needs_claim_alignment` 或 `not_claim`。

2. Reviewer sentence-level issue 定位
   - `services/api/app/agents/reviewer_agent.py` 新增 `sentence_issues`。
   - issue 定位到 section、paragraph_index、sentence_index、sentence。
   - Reviewer 可识别 claim alignment 缺口和 `significantly improved` 等 overclaim。
   - 存在 major sentence issue 时，`overall_decision` 不高于 `major_revision`。

3. Literature Metadata Editor
   - 新增 `GET /api/projects/{project_id}/literature`。
   - 新增 `PATCH /api/projects/{project_id}/literature/{literature_id}`。
   - 支持人工编辑 title、authors、year、doi、journal、metadata_status、human_verified。
   - 只有 `metadata_status=verified` 且 `human_verified=true` 的记录进入 `Verified references`。

4. PDF Parse Quality Report
   - `services/api/app/tools/pdf_parser.py` 新增 quality_score、quality_label、needs_manual_review 等字段。
   - `literature/literature_index.json` 同步记录 PDF quality 摘要。
   - Literature Agent 和 Reviewer 会纳入低质量 PDF 风险。

5. Analysis Provenance
   - 新增 `analysis/analysis_provenance.json`。
   - 记录 input_data_hash、analysis_function、generated_files、runtime、row_count、column_count、limitations、is_demo_data。
   - `evidence.json` 的 analysis claim 绑定 `analysis/analysis_provenance.json`。

6. 前端 v0.3 面板
   - 新增 ClaimAlignmentPanel、SentenceIssuesPanel、LiteratureMetadataPanel、AnalysisProvenancePanel。
   - Dashboard 新增“查看 Claim 对齐”“查看句子级审稿问题”“文献元数据核验”“查看分析来源”入口。
   - 后端不可用时 mock fallback 可渲染所有新增面板。

7. 新增验证与 E2E
   - 新增 v0.3 pytest 覆盖 claim alignment、sentence issue、literature PATCH、PDF quality、analysis provenance。
   - 新增 `scripts/validate_v03.py`。
   - 新增 Playwright 配置和 `apps/web/e2e/v03-dashboard.spec.ts`。

## 2. v0.3 仍未完成能力

1. 未做真实 DOI 联网核验。
2. 未做用户登录、多租户权限、审计日志和公网生产部署。
3. 未引入 Redis、Celery、PostgreSQL 或 LangGraph。
4. 未做真实统计检验和 p 值生成。
5. PDF quality 仍为规则评分，不是 OCR 或版面质量评估。
6. Reviewer 仍是规则检查器，不替代人工科研审稿。
7. Playwright 当前覆盖 mock fallback；真实后端 E2E 可在 v0.4 扩展。

## 6. 新增 API 列表

1. `GET /api/projects/{project_id}/claim-alignment`
   - 读取 `provenance/claim_alignment.json`。

2. `GET /api/projects/{project_id}/analysis/provenance`
   - 读取 `analysis/analysis_provenance.json`。

3. `GET /api/projects/{project_id}/literature`
   - 读取 `literature/literature_index.json`。

4. `PATCH /api/projects/{project_id}/literature/{literature_id}`
   - 更新指定文献 metadata。
   - 非法 DOI、year、title、authors、metadata_status 会被拒绝。

5. `GET /api/projects/{project_id}/review/sentence-issues`
   - 返回 `review_report.json` 中的 `sentence_issues`。

所有新增 API 都保留项目路径边界保护；缺文件返回 404。

## 10. Literature Metadata Editor 使用说明

前端：

1. 启动后端和前端。
2. 打开 dashboard。
3. 点击“文献元数据核验”。
4. 编辑 title、authors、year、doi、journal、metadata_status、human_verified。
5. 点击“保存”。

后端：

```http
GET /api/projects/demo_project/literature
PATCH /api/projects/demo_project/literature/lit_001
```

PATCH 示例：

```json
{
  "title": "Manual verified record",
  "authors": ["Human Reviewer"],
  "year": 2024,
  "doi": "10.1234/demo-record",
  "journal": "Manual Metadata Journal",
  "metadata_status": "verified",
  "human_verified": true
}
```

验收映射：

- 实现：`services/api/app/api/literature.py`
- schema：`services/api/app/schemas.py`
- 前端：`apps/web/components/LiteratureMetadataPanel.tsx`
- 测试：`services/api/tests/test_v03_literature_metadata.py`
- 验证：`scripts/validate_v03.py`

## 17. v0.4 建议方向

1. Reviewer sentence-level issue 增加精确修订 diff。
2. Literature Metadata Editor 增加变更历史、批量校验和导入导出。
3. PDF Parse Quality Report 增加页级可视化和 OCR fallback。
4. Analysis Provenance 增加脚本版本、参数、随机种子和环境锁定。
5. Playwright E2E 增加真实后端 workflow 场景。
6. 引入权限、审计日志、任务队列和数据库迁移前的安全设计。
