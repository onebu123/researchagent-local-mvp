# ResearchAgent v0.6 Acceptance Criteria

## 1. 目标

v0.6 的目标是在 v0.5 已支持安全 manuscript patch 的基础上，增量补齐多 patch 管理、patch item 人工编辑、冲突检测、合并预览、版本 diff、reviewer issue 与 manuscript version 的 provenance 反查，以及 audit log 本地完整性导出。

v0.6 不改变 v0.1-v0.5 的核心架构，不引入登录、多租户、数据库、队列、LangGraph、真实科研软件、真实 DOI 数据库、真实 OCR、真实查重或公网生产部署能力。

## 2. 必须保护的 v0.5 边界

- `validate_v01.py` 到 `validate_v05.py` 必须继续通过。
- 不得删除或破坏 v0.1-v0.5 核心输出文件。
- patch item edit 不得绕过 `patch_safety`。
- merge preview 不得修改 `manuscript/draft.md`。
- merge preview 不得自动生成或覆盖 manuscript version。
- issue resolution 只能基于 patch/version provenance 判断，不得假装语义已解决。
- audit export 不得包含 secret、API key 或内部绝对路径。
- mock fallback 和无 API key demo 必须继续可运行。

## 3. Patch Item 编辑验收标准

- 支持 `PATCH /api/projects/{project_id}/manuscript/patches/{patch_id}/items/{patch_item_id}`。
- 只允许编辑 `status=proposed` 的 patch。
- 只允许修改 `after` 和可选 `reason`。
- `before`、`issue_id`、`decision_id`、`related_claim_id`、`section`、`paragraph_index`、`sentence_index` 不可被 API 修改。
- 编辑后必须自动重新运行 `patch_safety`。
- patch item 必须记录 `manual_edits`、`latest_safety_result` 和 `item_status`。
- unsafe item 必须标记为 `blocked` 或 `needs_revision`，并且不能被确认应用到新 version。
- 支持 `POST /api/projects/{project_id}/manuscript/patches/{patch_id}/items/{patch_item_id}/safety-check` 手动重跑 safety。
- 每次 edit 和 safety-check 必须写入 audit log。

## 4. Patch Conflict 验收标准

- 支持 `POST /api/projects/{project_id}/manuscript/patches/conflicts/check`。
- 输出 `manuscript/patches/conflict_report_{id}.json`。
- 至少检测 `same_sentence`、`same_before_text`、`overlapping_location`、`same_claim`、`unsafe_item`。
- 同一 `before` 文本或同一句被多个 patch 修改时必须生成 major conflict。
- unsafe item 必须进入 conflict report。
- conflict check 必须写入 audit log。

## 5. Patch Merge Preview 验收标准

- 支持 `POST /api/projects/{project_id}/manuscript/patches/merge-preview`。
- 输出 `manuscript/patches/merges/merge_{id}.json` 和 `merge_{id}.preview.md`。
- merge preview 必须先运行 conflict detection。
- 存在 major conflict 时 `can_apply=false`。
- unsafe item 不得进入 safe items。
- merge preview 不得修改 `draft.md`，不得生成 new manuscript version。
- merge preview 必须写入 audit log。

## 6. Manuscript Diff 验收标准

- 支持 `POST /api/projects/{project_id}/manuscript/diffs/generate`。
- 支持 diff list、diff JSON、diff markdown preview 读取 API。
- 输出 `manuscript/diffs/diff_{id}.json` 和 `diff_{id}.md`。
- diff hunk 必须包含 added/removed 行。
- diff hunk 尽量关联 `related_issue_ids` 和 `related_claim_ids`。
- 生成 diff 不得修改任何 manuscript 文件。
- diff generation 必须写入 audit log。

## 7. Issue Resolution 验收标准

- 支持 `GET /api/projects/{project_id}/review/issue-resolution`。
- 输出 `reviews/issue_resolution.json`。
- confirmed patch 中实际 applied 的 issue 才能标记为 resolved。
- skipped item 不得标记为 resolved。
- 无 applied patch 的 issue 必须保持 unresolved。
- 该能力只基于 provenance，不做语义判定。

## 8. Audit Export 验收标准

- 支持 audit export list、JSON、markdown report API。
- 输出 `audit/exports/audit_export_{id}.json` 和 `audit_integrity_report_{id}.md`。
- export JSON 必须包含 `hash_chain_valid`、`first_invalid_index`、`entry_count` 和 `entries`。
- markdown report 必须明确说明这是 local integrity report，不是 production-grade tamper-proof audit system。
- export 内容不得包含 secret、API key 或内部绝对路径。
- export 操作必须写入 audit log。

## 9. 前端验收标准

- 新增 Patch Item Editor、Patch Conflict、Patch Merge、Manuscript Diff、Issue Resolution、Audit Export 面板。
- Dashboard 必须提供对应入口。
- Manuscript Patch 面板必须支持 item edit、safety-check、conflict check、merge preview 入口。
- Manuscript Version 面板必须支持打开 version diff。
- Audit 面板必须支持 audit export 入口。
- 后端不可用时 mock fallback 仍可渲染。
- `npm run typecheck`、`npm run build`、`npx playwright test` 必须通过。

## 10. 新增测试和验证

- 新增 v0.6 pytest 覆盖 patch item edit、patch conflict、patch merge、manuscript diff、issue resolution、audit export。
- 新增 `scripts/validate_v06.py`，必须完整验证 v0.1-v0.6 可信链路。
- `python -m compileall services\api scripts` 必须通过。
- `python -m pytest services\api\tests` 必须通过。
- `python scripts\seed_demo.py`、`python scripts\run_demo.py` 和 `python scripts\validate_v01.py` 到 `python scripts\validate_v06.py` 必须通过。

## 11. Playwright 产物策略

- `apps/web/playwright.config.ts` 必须配置：
  - `trace: "retain-on-failure"`
  - `video: "retain-on-failure"`
  - `screenshot: "only-on-failure"`
- `.gitignore` 必须忽略 Playwright trace、video、report 和 test result 产物。
