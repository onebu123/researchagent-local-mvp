# ResearchAgent v0.9 验收标准

## 1. v0.9 目标

ResearchAgent v0.9 的目标是在 v0.8 的精细 revision diff、metadata diff、PDF quality report、analysis comparison、audit classification 和 run diagnostics 基础上，增加可追踪的人工审阅状态流。

v0.9 不重写架构，不做公网生产，不引入登录、多租户、PostgreSQL、Redis、Celery、LangGraph，不接真实科研软件、真实 DOI 数据库、真实 OCR、真实湿实验仪器或真实查重。

## 2. 必须保护的 v0.8 基线

- `python scripts/validate_v01.py` 到 `python scripts/validate_v08.py` 必须持续通过。
- 不得删除或破坏 v0.1-v0.8 关键输出，包括 literature index、metadata history、metadata diff/batch、PDF quality report、analysis provenance/comparisons、figure provenance、evidence、claim alignment、draft/refined manuscript、patch/merge/version/diff/revision diff、review/issue resolution、audit log/export 和 run history。
- 不得破坏 `claim_id` 稳定性、Evidence Checklist、Claim Alignment、Reviewer sentence-level issue、patch_safety。
- 不得自动修改 `manuscript/draft.md`、已有 manuscript version、patch、revision diff 或 `literature/literature_index.json`。
- 不得伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性、因果关系、真实实验结论或 verified reference。
- 不得执行 OCR，不得把低质量 PDF 页面标记为可靠全文来源。
- 不得泄露 secret、API key 或内部绝对路径。
- 无 API key 环境必须继续完整跑通 demo，前端必须继续支持 mock fallback。

## 3. Revision Diff Reviewer

必须新增 `projects/{project_id}/manuscript/revision_diffs/revision_diff_reviews.jsonl`，记录每个 revision diff change 的人工审阅状态。

每条记录必须包含：

- `review_id`
- `revision_diff_id`
- `change_id`
- `human_status`
- `reason`
- `created_at`
- `source`

`human_status` 只允许：

- `accepted`
- `rejected`
- `needs_rewrite`
- `needs_evidence`

必须新增 `revision_diff_review_summary.json`，统计 total_changes、reviewed、accepted、rejected、needs_rewrite、needs_evidence、unreviewed，并展示每个 change 的 latest status、latest reason 和 review_count。

验收标准：

- 可以通过 API 提交 revision diff review。
- 非法 `human_status` 返回 400 或 422。
- review 不修改 manuscript、version、patch 或 diff。
- summary 正确统计 reviewed / unreviewed。
- 写入操作必须写 audit log。

## 4. Metadata Review Workflow

必须新增 `projects/{project_id}/literature/metadata_review_actions.jsonl`，把 metadata diff、batch review 和人工动作串成可追踪的 metadata review workflow。

每条记录必须包含：

- `action_id`
- `literature_id`
- `field`
- `action`
- `source_history_id`
- `reason`
- `created_at`
- `source`

`action` 只允许：

- `accept_change`
- `reject_change`
- `needs_verification`
- `request_revert`

必须新增 `metadata_review_summary.json`，统计 total_actions 和各 action 数量，并展示每个 literature_id + field 的 latest_action、latest_reason、review_count。

验收标准：

- 可以提交 metadata review action。
- 非法 action 返回 400 或 422。
- action 不修改 `literature_index.json`。
- `request_revert` 只表示请求撤销，不实际执行撤销。
- 写入操作必须写 audit log。

## 5. PDF Page Review Workflow

必须新增 `projects/{project_id}/literature/pdf_page_reviews.jsonl`，对低质量页、疑似扫描页或 OCR not configured 页面记录人工 review 状态。

每条记录必须包含：

- `review_id`
- `source_file`
- `page_number`
- `auto_quality_signal`
- `human_status`
- `reason`
- `created_at`
- `source`

`human_status` 只允许：

- `accepted_as_readable`
- `needs_ocr`
- `ignore_page`
- `needs_manual_check`

必须新增 `pdf_page_review_summary.json`，统计 total_reviews 和各 human_status 数量，并展示每个 PDF 页面 latest status、auto_quality_signal 和 review_count。

验收标准：

- 可以提交 PDF page review。
- 非法 `human_status` 返回 400 或 422。
- `needs_ocr` 只做人工标记，不执行 OCR，不生成 OCR 文本。
- 不得自动把低质量页变成可靠全文。
- 写入操作必须写 audit log。

## 6. Analysis Comparison Timeline

必须新增 `services/api/app/tools/analysis_timeline.py`，生成 `projects/{project_id}/analysis/analysis_timeline.json`。

timeline 必须只基于已有 `runs/run_history.json` 和 `analysis/comparisons/*.json` 生成，不得伪造不存在的 run 或 comparison。

验收标准：

- `analysis_timeline.json` 存在。
- timeline 至少能关联一个 run 或 comparison。
- 未关联 run 的 comparison 进入 `unlinked_comparisons`。
- 写入操作必须写 audit log。

## 7. Audit Report Filters

必须新增 `services/api/app/tools/audit_filter_export.py`，支持按 `event_category`、`risk_level`、`entity_type`、`entity_id` 过滤本地 audit log 并导出。

输出目录：

- `projects/{project_id}/audit/filtered_exports/`

输出文件：

- `audit_filtered_export_{id}.json`
- `audit_filtered_report_{id}.md`

验收标准：

- 可以按 `event_category` 过滤导出。
- 可以按 `risk_level` 过滤导出。
- 过滤结果为空时也生成 report，并说明 no matching entries。
- report 必须说明这是 local filtered audit report，不是生产级审计。
- export/report 不包含 secret、API key 或内部绝对路径。
- 写入操作必须写 audit log。

## 8. 新增 API

必须新增：

- `POST /api/projects/{project_id}/manuscript/revision-diffs/{revision_diff_id}/changes/{change_id}/review`
- `GET /api/projects/{project_id}/manuscript/revision-diffs/reviews`
- `POST /api/projects/{project_id}/literature/{literature_id}/metadata-review`
- `GET /api/projects/{project_id}/literature/metadata-review-actions`
- `POST /api/projects/{project_id}/literature/pdf-page-review`
- `GET /api/projects/{project_id}/literature/pdf-page-reviews`
- `GET /api/projects/{project_id}/analysis/timeline`
- `POST /api/projects/{project_id}/audit/filtered-export`
- `GET /api/projects/{project_id}/audit/filtered-exports`
- `GET /api/projects/{project_id}/audit/filtered-exports/{export_id}`
- `GET /api/projects/{project_id}/audit/filtered-exports/{export_id}/report`

所有 API 必须：

- 做路径越界保护。
- 文件不存在返回 404 或清晰空结构。
- 输入非法返回 400 或 422。
- 不返回内部绝对路径。
- 不自动修改 manuscript、literature_index、OCR 文本或 analysis run。
- 写入操作写 audit log。

## 12. 不做的功能

v0.9 不做：

- 用户登录、多租户、公网部署。
- Redis、Celery、PostgreSQL、LangGraph。
- MATLAB、Origin、COMSOL、ImageJ 或真实湿实验仪器。
- 真实 DOI 联网核验、真实 OCR、真实查重。
- 绕过 AI 检测。
- 完整 LaTeX 编译。
- 复杂 UI 重构。
- 自动生成 p 值、统计显著性、因果推断。
- 自动把 placeholder 文献变成 verified。
- 自动覆盖 `manuscript/draft.md`。
- 把 audit filtered export 宣称为生产级审计。
- 自动重试失败任务。
