# ResearchAgent v0.5 验收报告

## 1. v0.5 状态

ResearchAgent v0.5 已完成并通过本地验收。v0.5 在 v0.4 基础上增量实现 manuscript patch 草稿、patch preview、人工确认、manuscript versioning、audit hash chain 和真实后端 Playwright E2E，不重写原有 workflow 架构，不覆盖 `manuscript/draft.md`。

## 2. v0.5 已完成能力

- accepted revision decision 生成 proposed manuscript patch：`services/api/app/tools/manuscript_patch.py`、`services/api/app/api/manuscript.py`。
- rejected revision decision 不进入 patch item：`test_v05_manuscript_patch.py`。
- 同一 sentence issue 存在多条 decision 时，只取最新 decision；最新为 accepted 才进入 patch，避免重复应用同一句修订。
- patch safety 检查数字、单位、p 值、DOI、强结论、claim_id 和 before 定位：`services/api/app/tools/patch_safety.py`、`test_v05_patch_safety.py`。
- patch preview markdown：`projects/demo_project/manuscript/patches/patch_001.preview.md`。
- patch confirm/reject API：`POST /api/projects/{project_id}/manuscript/patches/{patch_id}/confirm`。
- confirmed patch 生成新版本，不覆盖 draft：`projects/demo_project/manuscript/versions/manuscript_v001.md`、`test_v05_manuscript_versions.py`。
- version history：`projects/demo_project/manuscript/versions/version_history.json`。
- audit hash chain：`services/api/app/tools/audit_log.py` 增加 `prev_hash`、`entry_hash` 和 `verify_audit_hash_chain`。
- audit verify API：`GET /api/projects/{project_id}/audit/verify`。
- 前端新增 Manuscript Patch、Manuscript Versions、Audit Hash Chain 面板：`apps/web/components/ManuscriptPatchPanel.tsx`、`ManuscriptVersionPanel.tsx`、`AuditVerifyPanel.tsx`。
- Playwright 覆盖真实后端 patch flow 和 mock fallback：`apps/web/e2e/v05-patch-flow.spec.ts`、`v03-dashboard.spec.ts`。

## 8. Patch Safety 规则

实现文件：`services/api/app/tools/patch_safety.py`。

规则：

- `before` 必须存在于 source manuscript。
- `after` 不得为空。
- 不得修改或新增数字。
- 不得修改或新增单位。
- 不得引入 p 值。
- 不得引入 DOI。
- 不得引入 strong conclusion terms。
- `related_claim_id` 如果存在，必须存在于 `provenance/evidence.json`。

测试：`services/api/tests/test_v05_patch_safety.py`。

## 9. Manuscript Versioning

实现文件：`services/api/app/tools/manuscript_patch.py`。

规则：

- confirm patch 后生成 `manuscript/versions/manuscript_v001.md`。
- `draft.md` 不被覆盖。
- 无法定位 `before` 时跳过 item 并记录 skipped item。
- version history 记录 source patch、source decisions、source issues、applied/skipped item 和 warnings。
- 新版本保留 Evidence Checklist 和原有 claim_id。

测试：`services/api/tests/test_v05_manuscript_versions.py`。

## 10. Audit Hash Chain

实现文件：`services/api/app/tools/audit_log.py`。

规则：

- 每条 audit 记录包含 `prev_hash` 和 `entry_hash`。
- 第一条 `prev_hash="GENESIS"`。
- `entry_hash` 基于不含 `entry_hash` 的 canonical JSON 计算 SHA256。
- 下一条 `prev_hash` 等于上一条 `entry_hash`。
- `GET /api/projects/{project_id}/audit/verify` 返回 `valid`、`checked_entries`、`first_invalid_index`、`errors`。
- 这是本地完整性辅助，不是生产级不可篡改审计。

测试：`services/api/tests/test_v05_audit_hash_chain.py`。
