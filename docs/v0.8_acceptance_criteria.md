# ResearchAgent v0.8 验收标准

## 1. v0.8 目标

ResearchAgent v0.8 的目标是在 v0.7 的 safe merge、version lineage、issue human review 基线上，增量提升科研草稿系统的可信修订控制、metadata 审阅精度、PDF/analysis 质量报告，以及本地审计和运行历史可用性。

v0.8 不重写架构，不引入登录、多租户、PostgreSQL、Redis、Celery、LangGraph 或公网生产能力；不接真实科研软件、真实 DOI 数据库、真实 OCR、真实查重或真实湿实验仪器。

## 2. 必须保护的 v0.7 基线

- `python scripts/validate_v01.py` 到 `python scripts/validate_v07.py` 必须继续通过。
- 不得删除或破坏 v0.1-v0.7 已有核心输出文件。
- 不得破坏 `claim_id` 稳定性、Evidence Checklist、Claim Alignment、Reviewer sentence-level issue 检查或 `patch_safety`。
- patch item edit 不得修改 `before`、`issue_id`、`decision_id`、`related_claim_id`、`section`、`paragraph_index`、`sentence_index`。
- merge preview 和 merge confirm 均不得覆盖 `manuscript/draft.md`。
- merge confirm 只能生成新 manuscript version，不得覆盖已有 version。
- conflict patch 不得自动合并。
- placeholder 文献不得自动标记为 verified。
- 不得伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性、因果关系或真实实验结论。
- audit export 和 audit log 不得包含 secret、API key 或内部绝对路径。
- 前端后端不可用时必须继续支持 mock fallback。
- 无 API key 环境必须继续完整跑通 demo。

## 3. Revision Line Diff 验收标准

- 新增 `services/api/app/tools/revision_line_diff.py`。
- 新增输出目录 `manuscript/revision_diffs/`。
- 生成 `revision_diff_{id}.json`，包含 `revision_diff_id`、`base_file`、`target_file`、`created_at`、`summary` 和 `changes`。
- 每条 change 至少包含 `change_id`、`section`、`paragraph_index`、`sentence_index`、`line_start`、`line_end`、`before`、`after`、`change_type`、`related_issue_ids`、`related_claim_ids`、`safety_status`、`notes`。
- confirmed patch 或 merge-generated version 后可生成 revision line diff。
- revision diff 至少包含 1 个 change，且能关联 issue_id 或 claim_id。
- revision diff 只读 manuscript 文件，不得修改 `draft.md`、version 文件或任何 patch 文件。
- 新增 API：
  - `POST /api/projects/{project_id}/manuscript/revision-diffs/generate`
  - `GET /api/projects/{project_id}/manuscript/revision-diffs`
  - `GET /api/projects/{project_id}/manuscript/revision-diffs/{revision_diff_id}`
- 前端新增 `apps/web/components/RevisionLineDiffPanel.tsx`，展示 section、paragraph、sentence、line、before/after、related issues/claims 和 safety status。

## 4. Literature Metadata Field Diff 验收标准

- 新增 `services/api/app/tools/literature_metadata_diff.py`。
- 新增输出 `literature/metadata_diff_report.json`。
- report 必须包含 `generated_at` 和 `records`。
- 每条 change 必须包含 `field`、`old_value`、`new_value`、`change_type`、`source_history_id` 和 `revert_suggestion`。
- revert suggestion 只能生成撤销建议，不得自动执行 revert，不得修改 `literature_index.json`。
- 不得自动把 placeholder/extracted 改成 verified。
- 不得自动生成 DOI、作者、年份、期刊或页码。
- 新增 API：
  - `GET /api/projects/{project_id}/literature/metadata-diff`
  - `POST /api/projects/{project_id}/literature/{literature_id}/metadata/revert-suggestion`
- 写入或生成建议的操作必须写 audit log。
- 前端新增 `apps/web/components/LiteratureMetadataDiffPanel.tsx`，展示 field diff 和 revert suggestion。

## 5. Literature Metadata Batch Review 验收标准

- 新增输出 `literature/metadata_review_batch.json`。
- batch review 包含 `batch_id`、`created_at`、`summary`、`records`。
- summary 必须统计 total、placeholder、extracted、verified、needs_review。
- placeholder 文献必须推荐 `manual_review_required`。
- verified 且 `human_verified=true` 的文献推荐 `no_action`。
- batch review 不得修改 `literature_index.json` 或任何 metadata 状态。
- 新增 API：
  - `POST /api/projects/{project_id}/literature/metadata-review-batch`
- 前端新增 `apps/web/components/LiteratureMetadataBatchPanel.tsx`，展示状态统计、recommended_action 和 reasons。

## 6. PDF Quality Report 验收标准

- 新增或扩展 PDF 质量工具，输出 `literature/pdf_quality_report.json`。
- report 必须包含 `generated_at`、`pdfs`、`summary`。
- 每个 PDF record 必须包含 `source_file`、`metadata_file`、`quality_label`、`quality_score`、`page_count`、`low_quality_pages`、`empty_pages`、`suspected_scanned_pages`、`issue_categories`、`recommended_action`。
- `issue_categories` 至少包含 low text、empty page、fallback parser、many warnings、OCR not configured 相关计数。
- suspected scanned pages 只能基于页级文本量很低且 page_count 大于 0 的本地推断。
- OCR 仍只做预留，不得标记 OCR 已执行。
- 低质量页不得被当作可靠全文证据。
- Reviewer 可以把 PDF quality 风险纳入 metadata/citation issues，但不得因此伪造引用或强制失败。
- 新增 API：
  - `GET /api/projects/{project_id}/literature/pdf-quality-report`
- 前端新增 `apps/web/components/PDFQualityReportPanel.tsx`。

## 7. Analysis Provenance Compare 验收标准

- 新增 `services/api/app/tools/analysis_compare.py`。
- 新增输出目录 `analysis/comparisons/`。
- 生成 `analysis_compare_{id}.json`。
- comparison 必须包含 `comparison_id`、`base_provenance`、`target_provenance`、`created_at`、`summary`、`diffs`。
- diffs 必须包含 `parameters`、`input_data_hash`、`output_file_hashes`、`runtime`、`warnings`、`limitations`。
- compare 只能比较已有 provenance 文件，不得伪造运行结果或分析输出。
- 新增 API：
  - `POST /api/projects/{project_id}/analysis/compare`
  - `GET /api/projects/{project_id}/analysis/comparisons`
  - `GET /api/projects/{project_id}/analysis/comparisons/{comparison_id}`
- 前端新增 `apps/web/components/AnalysisComparePanel.tsx`。

## 8. Audit Event Classification 验收标准

- 扩展 `services/api/app/tools/audit_log.py`。
- 新 audit entry 必须包含 `event_category`、`risk_level`、`entity_type`、`entity_id`。
- `event_category` 可取 `workflow|file|literature|review|patch|merge|version|audit|analysis|system`。
- `risk_level` 可取 `low|medium|high`。
- `entity_type` 可取 `project|file|literature|review_issue|patch|merge|version|audit_export|analysis|workflow`。
- 不得破坏 v0.5-v0.7 audit hash chain 验证。
- audit verify 必须继续 valid。
- audit export 必须包含新增分类字段，且不得泄露 secret、API key 或内部绝对路径。
- 前端 `AuditLogPanel.tsx` 支持展示和简单过滤 event_category、risk_level、entity_type、entity_id。

## 9. Run History Diagnostics 验收标准

- 扩展 `services/api/app/tools/run_history.py`。
- 每条 run entry 必须包含 `failure_diagnostics`、`recoverable`、`retry_hint`。
- 成功 run 也必须包含 diagnostics 字段，错误字段为 null 或空数组。
- 失败 run 必须记录 `failed_step`、`likely_cause` 和 `suggested_recovery`。
- 不引入队列，不自动重试。
- 前端 `RunHistoryPanel.tsx` 展示 diagnostics、recoverable、retry_hint。

## 15. v0.8 不做的功能

- 不做用户登录、多租户或公网部署。
- 不接 Redis、Celery、PostgreSQL 或强制 LangGraph。
- 不接 MATLAB、Origin、COMSOL、ImageJ 或真实湿实验仪器。
- 不做真实 DOI 联网核验、真实 OCR、真实查重或完整 LaTeX 编译。
- 不做绕过 AI 检测。
- 不做复杂 UI 重构。
- 不自动生成 p 值、统计显著性或因果推断。
- 不把 placeholder 文献自动变成 verified。
- 不自动覆盖 `manuscript/draft.md`。
- 不把 PDF low quality 页面当可靠全文来源。
- 不把 audit classification 当作权限系统。
- 不自动重试失败任务。
