## 5. Agent 工作流执行顺序

完整 workflow 顺序来自 `ResearchWorkflow.agents`：

1. `literature`：`Literature Agent`，读取文献并生成文献综述/关键发现。
2. `topic`：`Topic & Novelty Agent`，生成候选选题与新颖性风险。
3. `analysis`：`Analysis Agent`，读取 CSV 并生成统计分析。
4. `figure`：`Figure Agent`，基于 CSV 生成图表和 provenance。
5. `manuscript`：`Manuscript Agent`，生成论文 Markdown 初稿。
6. `refinement`：`Refinement Agent`，润色初稿，不新增事实。
7. `reviewer`：`Reviewer Agent`，审查 evidence、placeholder 和过度表述。
8. `provenance`：`Provenance Agent`，生成 claim evidence JSON。

完整运行时，`workflow_status` 从 `running` 更新为 `completed`，`current_step` 最终为 `completed`。单步运行只允许上述 step 名称。

## 8. 当前安全边界有哪些

| 安全边界 | 当前实现 | 剩余风险 |
| --- | --- | --- |
| CORS | 仅允许 `http://localhost:3000` 和 `http://127.0.0.1:3000`，允许 credentials。 | v0.1 无登录态，未来引入 Cookie/session 后需补 CSRF 与更严格方法/头策略。 |
| 输入 DTO | 项目创建、workflow step、响应结构使用 Pydantic schema。 | 部分 path 参数如 `project_id` 主要在 storage 层清洗；未实现全局路径参数正则约束。 |
| 上传后缀 | 文献限制 `.pdf/.md/.markdown/.txt`，数据限制 `.csv`。 | 未校验 MIME、magic number、大小、病毒扫描、PDF 安全解析。 |
| 文件名清洗 | `safe_filename` 使用 `Path(...).name` 去掉目录，并将非法字符替换为 `_`。 | 未处理同名覆盖策略；未做内容级安全扫描。 |
| 项目 ID 清洗 | `safe_segment` 仅保留字母、数字、下划线、点和短横线，并剥离边界点/下划线。 | 项目创建接口生成随机 id；若后续允许用户指定 id，需要补 API 层校验和冲突策略。 |
| 路径越界保护 | `ensure_inside_project` 使用 `Path.resolve()` 和 `relative_to(root)` 校验目标路径在项目目录内。 | 未验证符号链接逃逸场景；v0.2 需加入软链/zip slip 等文件测试。 |
| 输出读取保护 | 读取 output 前再次校验路径在项目目录内。 | 输出记录来自 SQLite，未来若开放用户写 output metadata，需补授权和更强校验。 |
| SQL 注入边界 | SQLite 查询使用参数化 `?`，无字符串拼接用户输入 SQL。 | 未实现复杂过滤/排序接口；未来添加时需白名单映射。 |
| 密钥边界 | `LLM_API_KEY` 只从环境变量读取；README/.env.example 不包含真实 key。 | 未实现 secret scanning/CI 门禁。 |
| LLM 失败降级 | 真实 LLM 调用失败自动 fallback 到 mock，不把异常堆栈返回前端。 | fallback 可能掩盖真实 LLM 质量/可用性问题；报告需明确 mode。 |
| 学术合规边界 | 不生成真实引用、DOI、p 值、因果结论；图表 provenance 标记 `is_ai_generated=false`。 | 仍需人工核验真实文献、真实实验数据和 claim。 |
| 认证授权 | 未实现。 | 这是 v0.1 最大安全缺口；目前只适合本地 demo，不适合多用户或公网部署。 |
| 审计日志 | 未实现独立审计日志。 | 无法追踪用户操作、上传来源、工作流触发者。 |

## 10. v0.2 建议开发计划

### P0：把 v0.1 从本地 demo 提升到可控试用

1. 增加用户、项目成员、角色权限和服务端授权策略。
2. 为所有项目级 API 增加 subject/project/action 授权校验。
3. 增加审计日志：项目创建、上传、运行 workflow、读取输出、删除/覆盖文件。
4. 增加上传安全：文件大小限制、MIME/magic number、PDF 解析沙箱、同名文件策略。
5. 增加 CI：Python compile/pytest、前端 typecheck/build/audit、v0.1 validation。

### P1：补齐科研可信链路

1. 接入真实 PDF 解析和文本抽取，记录解析 provenance。
2. 增加文献元数据表、引用管理、DOI 校验和人工核验状态。
3. 增加统计检验计划，但默认不自动生成 p 值；必须绑定数据、方法和人工确认。
4. 扩展 `evidence.json`：claim 与章节、数据文件、分析摘要、图表、人工核验状态逐条绑定。
5. 增加图表版本管理和可复现实验记录。

### P2：增强 Agent 与工作流

1. 引入 LangGraph 或等价工作流引擎，支持重试、跳过、失败恢复和状态持久化。
2. 为每个 Agent 增加输入/输出契约测试和 mock 边界说明。
3. 增加真实 LLM 模式的最小 eval 集，记录模型、prompt、温度、失败样本。
4. 将 hard-coded 候选选题、审稿规则和 provenance claim 改为可配置策略。
5. 增加工作流取消、运行历史和 step-level 日志。

### P3：提升产品与交付能力

1. 前端增加项目创建页、项目详情页、输出详情/下载页、运行历史页。
2. 前端增加空态、错误态、上传进度、输出预览和图表预览。
3. 增加 Playwright 关键路径：加载项目、上传 CSV、运行 workflow、查看输出。
4. SQLite 迁移到 PostgreSQL，补 migration、索引、备份和回滚方案。
5. 增加 Docker/部署配置、健康检查、日志、metrics 和基础告警。

### P4：验收门禁

1. v0.2 必须有 API 权限负向测试：未登录、无权限、跨项目、异常 project_id。
2. 必须有上传安全负向测试：非法后缀、路径穿越、超大文件、伪 MIME。
3. 必须有 e2e smoke：项目创建、上传 CSV、完整 workflow、输出读取。
4. 必须保留 mock/placeholder 披露，不允许 demo 内容进入真实论文路径。
