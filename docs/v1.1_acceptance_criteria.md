# ResearchAgent v1.1 验收标准

v1.1 在 v1.0 Local MVP 基础上增加 Literature Intelligence 能力，仍然是本地研究辅助工具，不是生产系统、公开服务、同行评审结论或科学事实验证系统。

## 必须能力

- LLM 客户端支持 `LLM_MODE=mock|live`；无 API key 时必须可用 mock fallback；live 使用 OpenAI-compatible `/chat/completions`。
- LLM 状态与测试 API 不暴露 API key：`GET /api/system/llm/status`，`POST /api/system/llm/test`。
- Prompt 存放在 `services/api/app/prompts/`，至少包含 `literature_answer_v1`、`citation_support_v1`、`metadata_extraction_v1`、`bibtex_generation_v1`。
- LLM 调用日志写入 `projects/{project_id}/llm/llm_calls.jsonl`，只保存摘要、hash、token/cost 占位、状态与错误类别，不保存 API key、完整 prompt、绝对路径。
- Literature RAG 使用本地 parsed literature 文本生成 `literature/rag/chunks.jsonl`、`rag_index.json`、`rag_answers.jsonl`；回答必须包含真实 `source_passages` 或 `unsupported_notes`。
- Source passage evidence 输出 `provenance/source_passage_evidence.json`，每条记录绑定 `chunk_id`。
- Metadata lookup 默认 `mock_fixture` 且不联网；optional provider 只在显式选择时使用；结果不回写 `literature_index.json`。
- BibTeX 只为 `metadata_status=verified` 且 `human_verified=true` 的记录生成正式条目；未验证记录仅写 warning/comment。
- Citation support 输出 `provenance/citation_support_report.json`，状态限定为 `supported`、`partial`、`unsupported`、`needs_human_review`。
- 前端新增 Literature Intelligence 分组与 7 个面板，并保留 mock fallback。
- `python scripts/validate_v11.py` 必须调用 `validate_v1.py`，并在无 API key、无网络要求下通过。

## 禁止事项

- 不伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性、因果关系或真实实验结论。
- 不执行真实 OCR，不自动覆盖 `manuscript/draft.md`。
- 不记录 API key、secret、完整敏感 prompt 或机器绝对路径。
- 不引入登录、多租户、PostgreSQL、Redis、Celery、LangGraph、强制 PaperQA2、生产部署或 peer-review-ready 声明。
