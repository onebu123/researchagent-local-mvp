# ResearchAgent v0.7 Acceptance Criteria

## 1. v0.7 目标

ResearchAgent v0.7 的目标是在 v0.6 的 patch merge preview 基础上，增量支持 safe merge 的人工确认、merge-generated manuscript version、version lineage、patch conflict 可视化定位、issue resolution 人工复核、audit export 文件 hash manifest，以及更完整的真实后端 Playwright E2E。

v0.7 不重写架构，不引入登录、多租户、PostgreSQL、Redis、Celery、LangGraph，不接真实科研软件、真实 DOI 数据库、真实 OCR 或真实查重。

## 2. 必须保护的 v0.6 基线

- `validate_v01.py` 到 `validate_v06.py` 必须继续通过。
- 不得删除或破坏 v0.1-v0.6 核心输出文件。
- 不得破坏 claim_id 稳定性、Evidence Checklist、Claim Alignment、Reviewer sentence-level issue、patch_safety。
- 不得伪造 DOI、作者、年份、期刊、页码、p 值、统计显著性、因果关系或真实实验结论。
- 不得把 placeholder 文献自动标记为 verified。
- 不得把 AI 生成图伪装成实验图。
- patch item edit 不得修改 `before`、`issue_id`、`decision_id`、`related_claim_id`、`section`、`paragraph_index`、`sentence_index`。
- merge preview 和 merge confirm 均不得覆盖 `manuscript/draft.md`。
- merge confirm 不得覆盖已有 manuscript version，只能生成新 version。
- `can_apply=false` 的 merge 不得 confirmed。
- conflict patch 不得自动合并。
- issue resolution 只能基于 provenance 和人工复核状态，不得假装语义自动解决。
- audit export 和 manifest 不得包含 secret、API key 或内部绝对路径。
- mock fallback 和无 API key demo 必须继续可运行。

## 3. Safe Merge Confirmation 验收标准

- 新增 `POST /api/projects/{project_id}/manuscript/patches/merges/{merge_id}/confirm`。
- request body 支持 `decision=confirmed|rejected` 和可选 `reason`。
- 只能确认或拒绝已存在的 merge preview。
- `can_apply=true` 的 merge 可以 confirmed。
- `can_apply=false` 的 merge confirmed 必须返回 400 或 422，并说明存在 conflict 或 blocked item。
- rejected merge 不生成 manuscript version。
- confirmed merge 生成新的 `manuscript/versions/manuscript_v*.md`。
- confirmed/rejected merge 必须更新 merge JSON 状态字段。
- confirmed/rejected merge 必须写入 audit log。
- confirmed merge 必须写入 version history。
- confirmed merge 必须可生成或记录 manuscript diff。

## 4. Merge-generated Manuscript Version 验收标准

- version history entry 支持 `source_type=patch|merge`。
- merge-generated version 必须包含 `source_merge_id`。
- merge-generated version 必须包含 `source_patch_ids`。
- merge-generated version 必须包含 `source_decision_ids` 和 `source_issue_ids`。
- 新 version 文件必须保留 Evidence Checklist 和 claim_id。
- 如果任何 item 无法定位 `before` 文本，必须 skipped，不得强行替换。
- skipped item 对应 issue 不得被 issue resolution 标为 resolved。
- version generation 必须写入 audit log。

## 5. Patch Conflict 可视化验收标准

- `PatchConflictPanel.tsx` 可以展示 conflict report。
- 显示 `conflict_report_id`、summary、conflict list、`conflict_type`、`severity`、`resolution_required`。
- 每个 patch item ref 显示 `patch_id`、`patch_item_id`、`issue_id`、`section`、`paragraph_index`、`sentence_index`、`related_claim_id`、`before`。
- 按 `conflict_type` 分组。
- major conflict 有明显视觉标记。
- unsafe item 显示 safety blocked reasons。
- 支持点击 patch_id 或 issue_id 展开同 panel 相关信息。
- mock fallback 有 conflict 示例。

## 6. Version Lineage 验收标准

- 新增 `services/api/app/tools/version_lineage.py`。
- 新增输出 `manuscript/versions/version_lineage.json`。
- 新增 `GET /api/projects/{project_id}/manuscript/lineage`。
- lineage 包含 root draft、patch、merge、version、diff 节点。
- lineage edges 表示 `proposed_patch`、`included_in_merge`、`generated_version`、`has_diff` 等关系。
- lineage 不得伪造不存在的 patch、merge、version 或 diff 关系。
- 前端新增 `VersionLineagePanel.tsx`，用列表或树形结构展示 lineage。

## 7. Issue Resolution 人工复核验收标准

- 新增 `reviews/issue_resolution_reviews.jsonl`。
- 新增 `POST /api/projects/{project_id}/review/issue-resolution/{issue_id}/review`。
- `human_status` 只能是 `resolved|unresolved|needs_review`。
- 非法 `human_status` 返回 400 或 422。
- human review 必须写入 audit log。
- `issue_resolution.json` 可以新增 `human_review_summary`，但不得覆盖 auto provenance 结果。
- 前端新增或扩展面板，支持选择 `human_status`、填写 reason、展示 review history。

## 8. Audit Export File Manifest 验收标准

- 扩展 `services/api/app/tools/audit_export.py`。
- audit export 后生成 `audit/exports/audit_file_manifest_{id}.json`。
- manifest 包含关键项目文件相对路径、SHA256、size_bytes、category。
- manifest 至少包含 `manuscript/draft.md`、`provenance/evidence.json`、`reviews/review_report.json`、`audit/audit_log.jsonl`。
- manifest 路径必须是项目相对路径。
- manifest 不得包含 secret、API key 或内部绝对路径。
- hash 失败文件进入 warnings，不静默忽略。
- integrity report markdown 包含 manifest summary。
- 新增 `GET /api/projects/{project_id}/audit/exports/{export_id}/manifest`。
- 前端 `AuditExportPanel.tsx` 展示 manifest file_count、categories、file path、sha256、size_bytes。

## 9. 前端验收标准

- 新增 `VersionLineagePanel.tsx`。
- 新增 `IssueResolutionReviewPanel.tsx` 或在 issue resolution 面板中提供同等能力。
- 扩展 `PatchMergePanel.tsx`，支持 confirm/reject merge，显示 `can_apply`，有 conflict 时不允许 confirm。
- 扩展 `PatchConflictPanel.tsx`，支持分组、定位、major 高亮、blocked reasons。
- 扩展 `ManuscriptVersionPanel.tsx`，显示 `source_type=merge` 和 `source_merge_id`。
- 扩展 `ManuscriptDiffPanel.tsx`，显示 `related_issue_ids` 和 `related_claim_ids`。
- 扩展 `IssueResolutionPanel.tsx`，显示 auto status 和 human review summary。
- 扩展 `AuditExportPanel.tsx`，显示 file hash manifest。
- Dashboard 新增入口：确认 Merge、查看 Version Lineage、人工复核 Issue Resolution、查看 Audit File Manifest。
- 后端不可用时 mock fallback 继续可渲染。
- `npm run typecheck`、`npm run build`、`npx playwright test` 必须通过。

## 10. 新增测试要求

- 新增 `services/api/tests/test_v07_merge_confirm.py`。
- 新增 `services/api/tests/test_v07_version_lineage.py`。
- 新增 `services/api/tests/test_v07_issue_resolution_review.py`。
- 新增 `services/api/tests/test_v07_audit_manifest.py`。
- 新增或扩展 `apps/web/e2e/v07-merge-lineage.spec.ts`。
- pytest 必须覆盖 can_apply=true confirm、can_apply=false reject、rejected merge 不生成 version、draft.md hash 不变、version history merge provenance、lineage、human review、audit manifest。
- Playwright 必须覆盖真实后端 merge/lineage/issue review/audit manifest 链路，并保留 mock fallback E2E。

## 11. validate_v07.py 验收标准

`scripts/validate_v07.py` 必须验证：

- demo_project 存在并可运行完整 workflow。
- `validate_v01.py` 到 `validate_v06.py` 继续通过。
- 可以创建 accepted revision decision。
- 可以生成 patch。
- 可以生成 safe merge preview。
- `can_apply=true` merge 可以 confirmed。
- confirmed merge 生成新的 manuscript version。
- `draft.md` hash 不变。
- version history 记录 `source_type=merge` 和 `source_merge_id`。
- 可以生成 manuscript diff。
- `version_lineage.json` 存在。
- lineage 包含 patch、merge、version、diff 节点。
- 可以提交 issue resolution human review。
- `issue_resolution_reviews.jsonl` 存在。
- audit export manifest 存在。
- manifest 包含 draft.md、evidence.json、review_report.json、audit_log.jsonl。
- audit report 包含 manifest summary。
- 输出 `ResearchAgent v0.7 validation passed.`
