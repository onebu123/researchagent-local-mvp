# ResearchAgent v0.2 验收报告

生成日期：2026-06-05

## 1. 验收结论

ResearchAgent v0.2 已从“可运行科研 Agent Demo”增量升级为“初步可信的科研论文草稿系统”。当前版本保留 v0.1 轻量架构，不引入登录、多租户、Redis、Celery、PostgreSQL 或 LangGraph 强依赖。

核心结论：

- v0.1 验证仍通过。
- v0.2 新增可信链路验证通过。
- 后端 pytest、Python compileall、前端 typecheck/build/audit 均通过。
- 当前 demo 因全部文献 metadata 仍为 placeholder，Reviewer 给出 `major_revision`，符合 v0.2 验收预期。

## 2. 已实现功能清单

### PDF 文本解析

- 新增 `services/api/app/tools/pdf_parser.py`。
- 上传或 seed PDF 后保留原始 PDF，并生成：
  - `projects/demo_project/literature/parsed/demo_pdf_literature.txt`
  - `projects/demo_project/literature/parsed/demo_pdf_literature.metadata.json`
- PyMuPDF 不可用时使用基础 PDF literal text fallback，并在 metadata warnings 中记录。
- 解析失败时不删除原始 PDF，metadata 会写入 `parse_status=failed|unsupported`。

### 文献 metadata 与引用结构

- 新增 `services/api/app/tools/literature_index.py`。
- 生成 `projects/demo_project/literature/literature_index.json`。
- 每条文献记录包含 `literature_id`、`source_file`、`title`、`authors`、`year`、`doi`、`source_type`、`parsed_text_file`、`metadata_status`、`human_verified`。
- Markdown、TXT、PDF 均进入同一索引。
- placeholder metadata 不进入 Verified references。

### Figure provenance 增强

- 修改 `services/api/app/tools/plotting.py`。
- 每条 figure record 包含 `figure_id`、`figure_type`、`source_data`、`analysis_file`、`script_or_function`、`output_files`、`is_ai_generated`、`is_experimental_result`、`created_at`、`data_hash`、`warnings`。
- `data_hash` 使用 source CSV 的 SHA256。
- source CSV 不存在时抛出错误，不生成伪图。

### Evidence claim 扩展

- 修改 `services/api/app/agents/provenance_agent.py`。
- `provenance/evidence.json` 至少生成 3 条 claim：
  - `claim_001`：analysis_summary
  - `claim_002`：figure
  - `claim_003`：manuscript_results
- 每条 claim 包含 `claim_id`、`section`、`claim`、`evidence_type`、`data_file`、`analysis_file`、`figure_file`、`figure_provenance_file`、`manuscript_file`、`evidence_status`、`human_verified`。

### Manuscript Agent 增强

- 修改 `services/api/app/agents/manuscript_agent.py`。
- Results 仅基于 `analysis/result_summary.json` 和 `figures/figure_provenance.json`。
- `draft.md` 包含 Evidence Checklist，并列出 `claim_id`。
- References 分为：
  - `Placeholder literature records`
  - `Verified references`
- 当全部文献为 placeholder 时，明确写入：
  - `These records are placeholders and require manual verification before submission.`
- 不伪造 DOI、作者、年份、期刊、页码或统计结论。

### Reviewer Agent 增强

- 修改 `services/api/app/agents/reviewer_agent.py`。
- 从磁盘读取 `draft.md`、`refined.md`、`evidence.json`、`figure_provenance.json`、`result_summary.json`、`literature_index.json`。
- 输出结构包含：
  - `overall_decision`
  - `major_issues`
  - `minor_issues`
  - `citation_issues`
  - `evidence_issues`
  - `figure_issues`
  - `statistical_issues`
  - `overclaims`
  - `consistency_checks`
  - `recommended_revisions`
- 检查 claim_id、强结论词、figure provenance、source data hash、output_files、row_count/column_count 一致性、placeholder 文献风险。

### 后端 API

- 新增 `GET /api/projects/{project_id}/evidence`。

## 3. 未实现功能清单

v0.2 按范围明确不做：

- 用户登录、多租户权限、公网部署。
- Celery、Redis、PostgreSQL、强制 LangGraph。
- DOI 联网查询、真实引用数据库核验。
- 真实查重、绕过 AI 检测、完整 LaTeX 编译。
- MATLAB、Origin、COMSOL、ImageJ 或真实湿实验仪器接入。
- 真实统计显著性检验和 p 值生成。
- 复杂 UI 路由重构。
- 把 placeholder 文献伪装成 verified reference。

## 6. Agent 工作流执行顺序

v0.2 当前顺序：

1. Literature Agent
2. Topic & Novelty Agent
3. Analysis Agent
4. Figure Agent
5. Provenance Agent
6. Manuscript Agent
7. Refinement Agent
8. Reviewer Agent

调整原因：

- Provenance 需要在 Manuscript 前生成 `claim_id`。
- Manuscript 需要把 `claim_id` 写入 Evidence Checklist。
- Reviewer 需要检查最终 draft/refined、evidence、figure provenance 和 literature metadata。

## 8. 当前 mock 逻辑

- LLM client 默认 `LLM_MODE=mock`，无 API key 时仍可运行。
- `scripts/seed_demo.py` 生成 demo markdown、demo PDF、demo CSV。
- demo 文献 metadata 明确标记为 placeholder。
- 前端后端不可用时使用 `mockProject`、`mockEvidence`、`mockFigureProvenance`、`mockOutputContent`。
- demo 数据用于工作流验证，不被声明为真实实验结果。

## 9. 当前安全边界

- 上传文件限制后缀。
- 上传文件大小限制为 10MB。
- 上传目标目录限定为项目子目录。
- 文件读取使用 `storage_service.ensure_inside_project` 防止路径越界。
- API 不返回内部绝对路径。
- PDF 解析失败不删除原始文件，仅写 metadata warning。
- Manuscript 不伪造 DOI、年份、作者、期刊、页码、p 值或正式统计结论。
- Figure provenance 明确 `is_ai_generated=false`，不把 AI 图伪装成实验图。
- Reviewer 会将 placeholder literature 作为 citation risk。

## 12. v0.3 建议开发计划

1. 引入更可靠的 PDF 解析策略，补扫描 PDF/OCR 边界和表格提取。
2. 增加人工核验 UI，把 `human_verified` 从 JSON 字段升级为可操作状态。
3. 建立引用 metadata 编辑器，支持 DOI/作者/年份/期刊的人工录入与校验。
4. 增加 analysis provenance，记录数据清洗步骤、脚本版本和统计方法。
5. 将 Reviewer 规则拆成可配置 rule set，并生成可定位到 manuscript 行号的审稿意见。
6. 增加端到端 UI 测试，覆盖输出详情、Evidence 详情和图表来源详情。
7. 引入轻量任务日志和审计事件，不急于引入复杂队列。
